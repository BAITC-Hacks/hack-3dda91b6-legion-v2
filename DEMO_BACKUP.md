# Резервный показ OrgLens AI

Основной сценарий — заранее выполненный Astra-анализ в открытой вкладке; см. [DEMO.md](DEMO.md). Подготовить три разных резерва и обозначать их происхождение вслух. Автоматической подмены ошибочного semantic-ответа другим режимом нет.

| Резерв | Что действительно показываем | Обозначение |
| --- | --- | --- |
| Markdown и скриншоты Astra | Материалы уже завершённого semantic-запуска | «Заранее подготовленный результат», ID и время подготовки |
| Deterministic backend | Обработку выбранных DOCX без LLM | `LIVE ANALYSIS` + «Детерминированный анализ» |
| Offline demo | Локальный синтетический набор, без обработки выбранных файлов | `DEMO DATA` |

## 1. Сохранить настоящий результат до выступления

После успешного Astra-запуска оставить вкладку открытой и скачать заключение. Результат UI хранится только в памяти этой вкладки: обновление страницы, закрытие, сброс или новый анализ его удаляют. Восстановления результата из Markdown/JSON и постоянного хранения в приложении нет.

Перед скачиванием включить запрос каталога сохранения в браузере. Все материалы сохранить **внутри репозитория**, например:

```text
artifacts/prepared-semantic/
  prepared-semantic-<analysis_id>.md
  prepared-semantic-overview.png
  prepared-semantic-evidence.png
  prepared-semantic-conclusion.png
  provenance.txt
```

Это схема имён, а не обещание уже созданных файлов. В `provenance.txt` записать: «Заранее выполненный semantic-анализ Astra», время подготовки, `analysis_id`, имена редакций и происхождение документов. Сохранённый Markdown содержит `LIVE ANALYSIS` как происхождение данных из API; при показе файла отдельно пояснить, что это подготовленный отчёт, а не новый ответ сервера. Снимки экрана тоже обозначать как подготовленные материалы.

`artifacts/` исключён из Git. Не добавлять его принудительно, не коммитить DOCX, ответы API, цитаты или отчёты. Проверить, что Markdown и изображения читаются локально. Не копировать в эти материалы ключи или конфигурацию с секретами.

## 2. Deterministic fallback — настоящий backend без LLM

Подготовить отдельную вкладку с результатом заранее, сохранив основную вкладку Astra. На backend требуется режим `deterministic`; переключателя режима модели в UI нет. Если нужен новый запуск, оператор останавливает прежний процесс на 8000 и запускает из корня репозитория:

```powershell
$env:ANALYSIS_MODE = 'deterministic'
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Frontend должен использовать API (`VITE_USE_MOCK=false` либо переменная отсутствует). Для локального backend на 8000 оставить `VITE_API_BASE_URL` пустым; иначе проверить адрес нужного сервера. Эти значения задаются до запуска dev-сервера или сборки frontend; при изменении требуется перезапуск или пересборка, пока основной результат ещё не подготовлен. В отдельной вкладке выбрать два DOCX → «Анализировать изменения» → проверить `LIVE ANALYSIS` и «Детерминированный анализ». Ключ и сеть для внешней модели этому режиму не нужны. Backend и локальный frontend должны работать.

Фраза для перехода: «Переключаемся на детерминированную обработку выбранной пары DOCX без языковой модели. Это отдельный результат backend; семантическое заключение Astra сейчас не пересчитывается». Если резерв использует другую или синтетическую пару, сказать об этом явно. Выбрать пример функции и источников из текущего ответа: названия, пункты и находки могут отличаться от semantic-отчёта. Не переносить его числа или интерпретации в этот показ.

## 3. Offline fallback — DEMO DATA

Заранее установить зависимости и собрать frontend. Обычная live-сборка также содержит локальный демонабор:

```sh
npm ci
npm run build
npm run preview -- --port 4173
```

Открыть `http://127.0.0.1:4173` или адрес из вывода команды в резервной вкладке. Нажать «Загрузить демодокументы» → проверить `DEMO DATA` → «Анализировать изменения». Для этого потока после сборки не нужны backend и интернет: данные, шрифт и иконки локальные. `dist/index.html` открывать через preview, а не двойным щелчком.

Фраза для перехода: «Показываем автономный синтетический пример интерфейса. Эти данные и этапы подготовлены заранее и не относятся к анализу загруженных документов».

Маршрут для короткого показа: обзор и граф → «Сравнение функций» → строка с основаниями → Escape → «Риски и выводы» → вывод `NEEDS_REVIEW` → Escape → «Заключение» → «Сформировать заключение» → **«Скачать заключение»**. Если панель не закрывается с клавиатуры, нажать кнопку «Закрыть источники» перед навигацией.

Сохранить скачанный Markdown внутри ignored `artifacts/prepared-offline-demo/` и открыть его для проверки: в начале должна быть явная пометка о синтетических документах и цитатах. Получение файла проверяется отдельно от появления заключения на экране. Демо-цитаты не представлять документами Казахтелекома. Число находок в этом наборе не является метрикой реального анализа. Длительность конкретного маршрута проверить на репетиции; паузы чтения экранов не заменяют замер устного выступления.

## Во время сбоя

- Если вкладка с готовым Astra-результатом работает, продолжить её показ: новый запрос не требуется.
- Если вкладка потеряна, открыть подготовленный Markdown/скриншоты и назвать их материалами предыдущего запуска. Сохранённый JSON не загружается обратно в UI.
- Если нужен интерактивный резерв, использовать отдельно подготовленную deterministic-вкладку либо `DEMO DATA`. Не сбрасывать основную вкладку ради переключения.
- При незавершённом новом запросе «Сбросить демо» прекращает ожидание браузера, но не гарантирует остановку вычисления на сервере. После ошибки доступна кнопка «Загрузить демодокументы»; выбор синтетического примера всегда явный.

Полные Astra-запуски ранее занимали около 90–101 секунды. Лимиты ожидания — 150 секунд в frontend и 120 секунд на обращение backend к OpenAI без повторов. На сцене не запускать повторные платные запросы ради анимации и не выдавать подготовленный результат за мгновенную обработку.
