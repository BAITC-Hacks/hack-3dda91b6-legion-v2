# Резервный показ

## Подготовить до выступления

Установить зависимости и собрать приложение с обычными настройками live (`VITE_USE_MOCK=false` либо переменная отсутствует). Локальный набор `DEMO DATA` работает и в этой сборке:

```sh
npm ci
npm test
npm run build
```

Запустить локальный просмотр статической сборки:

```sh
npm run preview -- --port 4173
```

Открыть `http://127.0.0.1:4173` или адрес из вывода команды, нажать «Загрузить демодокументы» и проверить метку `DEMO DATA`. Пройти резервную часть [DEMO.md](DEMO.md). Держать терминал и вкладку открытыми. Для этого сценария после установки зависимостей и сборки не требуются backend или доступ к интернету: шрифт Golos Text, иконки и данные входят в сборку; внешние CDN не используются. `dist/index.html` не следует открывать двойным щелчком: используйте локальный сервер preview.

На последнем экране нажать «Скачать заключение». Сохранить полученный `.md` рядом с материалами выступления и проверить, что он открывается в текстовом редакторе. Этот резервный отчёт должен иметь пометку о синтетических данных. Если отдельно сохраняете live-отчёт, не выдавайте его за новый запуск анализа.

## Если live-demo прервалось

1. Если запрос завис или сбой произошёл после выбора файлов, нажать «Сбросить демо», затем «Загрузить демодокументы» и «Анализировать изменения». Отмена прекращает ожидание браузера; завершение вычисления на сервере этим не гарантируется.
2. Если включён API-режим и сервер недоступен, нажать «Загрузить демодокументы» прямо в сообщении об ошибке, затем «Анализировать изменения». Локальный сценарий доступен в обоих режимах и не требует перезапуска или пересборки.
3. Если dev-сервер не отвечает, запустить подготовленную сборку командой preview выше и открыть напечатанный адрес. При занятом порте Vite может выбрать другой.
4. Если браузер закрыт, открыть адрес работающего preview и повторить демопоток.

Проверить метку `DEMO DATA`. Не скрывайте переключение: «Серверный показ прервался. Переключаемся на локальный синтетический набор, чтобы показать интерфейс и структуру проверяемого результата». Автоматической подмены live-ответа демоданными нет.

## Полный отказ интерактивного показа

До выступления вручную сохранить скриншоты графа, открытой панели оснований и заключения. Также `npm run test:e2e` сохраняет снимки сценария в `test-results`; для этого нужен установленный Google Chrome и свободные frontend-порты 5175, 5176 и 5177 (для live-проверки используется backend на 8000). Проверить итоговые изображения перед использованием. При отказе браузера показать скачанный Markdown-отчёт в редакторе или пройти по скриншотам тот же сценарий, явно назвав их материалами синтетического demo.

Содержимое локального demo не подтверждает качество backend или модели. Покажите принцип проверки: изменение → функция → пункт документа → статус и рекомендация.
