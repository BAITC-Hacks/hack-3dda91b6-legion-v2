# Резервный показ

## Подготовить до выступления

Установить зависимости и собрать приложение при `VITE_USE_MOCK=true` в `.env.local`:

```sh
npm install
npm test
npm run build
```

Запустить локальный просмотр статической сборки:

```sh
npm run preview -- --port 4173
```

Открыть `http://127.0.0.1:4173` или адрес из вывода команды и пройти [DEMO.md](DEMO.md). Держать терминал и вкладку открытыми. Для локального mock-показа после установки зависимостей и сборки не требуются backend или доступ к интернету: шрифт Golos Text, иконки и данные входят в сборку; внешние CDN не используются. `dist/index.html` не следует открывать двойным щелчком: используйте локальный сервер preview.

На последнем экране нажать «Скачать заключение». Сохранить полученный `.md` рядом с материалами выступления и проверить, что он открывается в текстовом редакторе. Это резервный отчёт по синтетическим данным.

## Если live-demo прервалось

1. Если сбой произошёл после выбора файлов, нажать «Сбросить демо», затем «Загрузить демодокументы» и «Анализировать изменения».
2. Если включён API-режим и сервер недоступен, нажать «Загрузить демодокументы» прямо в сообщении об ошибке, затем «Анализировать изменения». Локальный сценарий доступен в обоих режимах и не требует перезапуска или пересборки.
3. Если dev-сервер не отвечает, запустить подготовленную сборку командой preview выше и открыть напечатанный адрес. При занятом порте Vite может выбрать другой.
4. Если браузер закрыт, открыть адрес работающего preview и повторить демопоток.

Не скрывайте переключение: «Переключаемся на локальный синтетический набор, чтобы показать интерфейс и структуру проверяемого результата».

## Полный отказ интерактивного показа

До выступления вручную сохранить скриншоты графа, открытой панели оснований и заключения. Также `npm run test:e2e` сохраняет снимки сценария в `test-results`; для этого нужен установленный Google Chrome и свободные frontend-порты 5175, 5176 и 5177 (для live-проверки используется backend на 8000). Проверить итоговые изображения перед использованием. При отказе браузера показать скачанный Markdown-отчёт в редакторе или пройти по скриншотам тот же сценарий, явно назвав их материалами синтетического demo.

Содержимое демо не подтверждает качество будущего парсинга или модели. Покажите принцип проверки: изменение → функция → пункт документа → статус и рекомендация.
