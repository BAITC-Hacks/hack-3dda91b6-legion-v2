## Исправления

- **P2 от PC2:** пустое или состоящее из пробелов объяснение больше не попадает в API как допустимый результат модели. Отбрасывается только конкретное предложение; исходный кандидат и остальные корректные предложения сохраняются. Добавлено предупреждение. Такая же защита действует для заголовка и рекомендации finding. Необязательная пустая аналитическая записка не отображается.
- При общей ответственности нескольких подразделений явный завершающий маркер владельца уточняет назначение конкретного подпункта. Упоминание подразделения внутри фразы, неизвестная аббревиатура и название проверяемого подразделения не меняют владельца. Общие соседние подпункты сохраняют коллективный контекст; запрет остаётся запретом.
- На локальных документах организатора исправлены только два лишних назначения: `5.3.2.а` теперь относится к ДИТААД, `5.3.2.б` — к ДОА. Количество извлечённых функций/прав/запретов изменилось с 452 на 450; остальные записи совпали с checkpoint-2. Подразделения: 3 → 5.
- Версия входного материала для `analysis_id` увеличена до `v2`, чтобы отличать результаты исправленного извлечения. Формат API сохранён.

## Воспроизведение тестовых DOCX с известными изменениями

Backend должен быть запущен по инструкции README. В семантическом режиме ключ загружает только backend. Следующие команды не читают ключ на стороне клиента:

```powershell
.venv\Scripts\python.exe -m scripts.smoke_known_answer
# Отдельный платный запрос к модели через запущенный backend:
.venv\Scripts\python.exe -m scripts.smoke_known_answer --mode semantic
```

При другом порте добавьте `--base-url http://127.0.0.1:8001`.

Скрипт сначала сохраняет синтетические документы и ожидаемые изменения, затем загружает файлы в `/api/analyze`. Проверяет:

1. Число подразделений 4 → 5 и создание департамента анализа.
2. Перенос отчёта о закупочных рисках из `5.1.2` BEFORE в `5.2.2` AFTER.
3. Отсутствие соответствия контролю аварийного восстановления, BEFORE `5.3.1`.
4. Дублирование проверки договоров между AFTER `5.1.2` и `5.2.1`.
5. Потенциальное совмещение проверки и утверждения договоров, AFTER `5.1.2` и `5.1.3`.
6. В semantic: документально указанное переименование ДЗ → ДС, записка с источниками обеих редакций.
7. Документ, ID, номер и точный текст каждого evidence; статусы экспертной проверки.

Результаты находятся только в игнорируемом `artifacts/known-answer/`. DOCX, ответы с исходными фрагментами, Markdown и снимки экрана в Git не добавляются. Автоматические backend-тесты проверяют синтетический сценарий без сети и оплаты.
