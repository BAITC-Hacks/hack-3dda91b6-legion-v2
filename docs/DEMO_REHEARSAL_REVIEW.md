## Область и методика

Проверены два отдельных резервных маршрута:

1. Настоящий deterministic backend с синтетическими known-answer DOCX, обычный браузерный UI, источники и скачивание Markdown. Это реальная обработка файлов без обращения к LLM.
2. Локальный `DEMO DATA` после остановки backend: явный выбор синтетического набора, просмотр результата и скачивание отдельного Markdown. Это заранее подготовленные данные, не новый анализ DOCX.

Для каждого маршрута фиксируется фактическое время от первой навигации к локальной production-сборке до проверки содержимого скачанного Markdown. Заранее запланированы шесть пауз чтения по 10 секунд; их фактическая продолжительность учитывается отдельно. Устная речь не измеряется; длительность автоматизированной репетиции с паузами не является длительностью выступления человека или бенчмарком системы. Подготовка серверов и файлов не включается в маршрут.

Исправлена только проверка в ignored-скрипте репетиции: для demo сверяется текст шаблона. Код продукта не менялся. После этого весь offline-маршрут повторён в новом контексте. Незавершённый проход не считается успешной репетицией и не включён в измерения успешного повтора выше.

## Практическая сверка инструкции с UI

Сверены названия разделов и кнопок в `src/App.tsx`, `Conclusion.tsx`, `EvidenceDrawer.tsx`, режимы в `AnalysisMetadata.tsx` и адаптере анализа. Уточнены только действия, важные для воспроизводимого показа:

- В [DEMO.md](../DEMO.md) явно указано закрытие панели оснований перед переходом к следующему разделу. Панель модальная; доступны Escape и кнопка «Закрыть источники».
- Подготовка API-режима теперь учитывает `VITE_USE_MOCK` и `VITE_API_BASE_URL` до запуска или сборки frontend. Пустой адрес использует локальный proxy на backend 8000; изменение переменных требует перезапуска dev-сервера или пересборки.
- В [DEMO_BACKUP.md](../DEMO_BACKUP.md) offline-маршрут заканчивается явным нажатием «Скачать заключение», сохранением и проверкой файла с пометкой о синтетических данных. Формирование заключения на экране само по себе не подтверждает скачивание.
- Для deterministic-резерва требуется называть фактическую пару документов и выбирать примеры из её ответа. Резервные синтетические DOCX могут отличаться от документов semantic-показа; фраза «те же документы» не используется автоматически.

Текст принятого semantic-выступления, его запланированная длительность и [JUDGES_QA.md](../JUDGES_QA.md) не переписывались. Код frontend/backend, README и SUBMISSION в рамках этой сверки не изменялись.
