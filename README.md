# OrgLens AI

Explainable Organizational Change Agent · HackAlem AI 2026 · спецтрек «Казахтелеком».

## Совместный запуск checkpoint-1

Python 3.12 и Node.js 22.13+; команды из корня репозитория. Backend и frontend запускаются в двух терминалах:

```powershell
# Терминал 1
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

```powershell
# Терминал 2
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. По умолчанию пользовательские DOCX идут в настоящий backend через Vite proxy; OpenAI-ключ для детерминированного режима не нужен. «Загрузить демодокументы» сохраняет автономный синтетический сценарий. Для проверки собранного frontend: `npm run build`, затем `npm run preview -- --port 5173` при работающем backend.

Backend `/api/health` доступен на порту 8000 напрямую и через frontend `/api/health`. Секреты остаются только в окружении backend. `.env.example` содержит настройки обеих частей; backend загружает `.env` только с явным `--env-file .env`, Vite читает `.env` и `.env.local` (в браузер экспортируются только `VITE_*`).

## Problem

После реорганизации нужно сопоставить подразделения и функции двух редакций документов: кто сохранился, кому передали ответственность, где появились потери, дублирование и потенциальные конфликты. Вывод без ссылки на исходный пункт трудно проверить.

## Solution

Русскоязычная панель сравнения «до → после»: граф преобразований, таблица функций и карточки выводов. Для каждого существенного вывода можно открыть документ, пункт, фрагмент, объяснение и рекомендацию. Итоговое заключение собирает результаты в одном месте.

## What is implemented

- Выбор пары DOCX до 10 МБ каждый для API и однокнопочный синтетический демосценарий.
- Поэтапная индикация обработки и повторный запуск через «Сбросить демо».
- Сводные показатели, граф подразделений, сопоставление функций и список выводов.
- Панель оснований с явным статусом «Требует проверки» (`NEEDS_REVIEW`).
- Аналитическое заключение со скачиванием в Markdown; состояния загрузки, недоступности API, некорректного ответа и пустого списка выводов.
- Сохранённый синтетический demo и подключённый через адаптер настоящий FastAPI backend.

## Architecture

React + TypeScript + Vite. UI получает общий объект анализа через сервисный адаптер; деморежим возвращает локальный JSON. API-адаптер отправляет `POST /api/analyze` с `multipart/form-data`: `before_file` и `after_file`.

Контракт результата: `analysis_id`, `before_document`, `after_document`, `units`, `transformations`, `function_matches`, `findings`, `summary`. Перед показом валидатор проверяет поля, ссылки на ID, основания и согласованность счётчиков. Правила адаптации ответа CORE к UI: [API_CONTRACT.md](API_CONTRACT.md); исходные типы — [src/types.ts](src/types.ts).

## Run

В каталоге проекта:

```sh
npm ci
npm run dev
```

Откройте локальный адрес из вывода Vite. Проверка и сборка:

```sh
npm test
npm run build
npm run test:e2e
```

`npm test` проверяет адаптер и оба формата данных. E2E использует установленный Google Chrome: порты 5175 (синтетическое demo), 5176 (обработка ошибок API) и 5177 (production build + настоящий CORE). Первые два сценария перехватывают API; live-сценарий загружает оба локальных DOCX в FastAPI и проверяет граф, функции, цитаты и скачивание заключения без перехвата. Backend запускается на 8000, либо используется уже работающий. Перед `npm run test:e2e` выполните `npm run build`; при отсутствии локальных DOCX только live-тест пропускается. Тестовые frontend-порты должны быть свободны.

По умолчанию включён реальный API. Для автономного mock-режима можно создать `.env.local`:

```dotenv
VITE_USE_MOCK=true
```

Реальный API используется при `VITE_USE_MOCK=false` или отсутствии этой переменной. Vite dev/preview перенаправляет `/api` на `http://127.0.0.1:8000`; при отдельном адресе сервера задайте `VITE_API_BASE_URL`, например `http://localhost:8000`. Сервер должен разрешать запросы с адреса frontend через CORS либо быть доступен за общим origin. После изменения переменных перезапустите Vite; для готовой сборки выполните `npm run build` заново. Секреты в `VITE_*` не хранятся: эти значения попадают в клиентскую сборку.

## Data

Все данные, названия документов и цитаты в демосценарии синтетические. Это не документы Казахтелекома. Сюжет: 3 подразделения становятся 4; «Цифровое развитие» разделено на «ИТ» и «Цифровые продукты», «Внутренний контроль» переименован в «Риски и комплаенс», «Эксплуатация сети» сохранена. Набор содержит 5 передач функций, 1 возможную потерю, 2 дублирования и 1 потенциальный конфликт.

В mock-режиме выбранные пользователем файлы не разбираются и не отправляются на сервер; кнопка анализа для них отключена. Результат доступен после выбора «Загрузить демодокументы». Индикатор этапов имитирует работу агента только в этом сценарии. При анализе своих файлов в API-режиме показано ожидание ответа без вымышленных этапов.

## Limitations

- Реальные DOCX обрабатываются backend CORE. PDF/TXT/OCR не поддерживаются; UI согласован с ограничением 10 MiB.
- Confidence в mock задан вручную и не является откалиброванной вероятностью.
- `VERIFIED` в демо означает наличие подготовленных оснований в синтетическом наборе, а не независимую проверку реальных документов.
- Отсутствие функции в новой редакции и потенциальный конфликт требуют экспертной проверки: `NEEDS_REVIEW`. Нельзя считать отсутствие найденной цитаты доказательством отсутствия функции.
- Заключение интерфейса собирается из текущих данных. Backend в режиме `semantic` также возвращает отдельное заключение модели с источниками (`summary.analytical_note`); это не юридическое заключение.
- Аутентификация, серверное хранение и производственная обработка конфиденциальных документов не реализованы.

## Backend CORE — запуск, анализ и evidence lock

Backend MVP для HackAlem AI 2026, спецтрек Казахтелеком. Сравнивает два DOCX и возвращает структурированный JSON с подразделениями, функциями, отношениями и точными источниками.

## Быстрый запуск (Windows PowerShell, Python 3.12)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Swagger: http://127.0.0.1:8000/docs. Машиночитаемый контракт: http://127.0.0.1:8000/openapi.json.

`requirements-lock.txt` фиксирует проверенное окружение, включая тестовые зависимости. Диапазоны прямых зависимостей находятся в `requirements.txt` и `requirements-dev.txt`.

## Первый DOCX → JSON diff

В локальном `data/` ожидаются:

- `Положение_о_внутреннем_аудите_редакция_8_обезличено.docx` — BEFORE;
- `Положение_о_внутреннем_аудите_редакция_9_обезличено.docx` — AFTER.

```powershell
$before = (Get-ChildItem data -Filter '*_8_*.docx').FullName
$after = (Get-ChildItem data -Filter '*_9_*.docx').FullName
.\.venv\Scripts\python.exe -m backend.cli $before $after --output artifacts\comparison.json
```

CLI принимает любые два DOCX, а не только контрольные редакции. `artifacts/`, входные DOCX и `.env` исключены из Git. Сохраняемый JSON содержит исходные фрагменты; он остаётся локальным. В репозитории нет копий документов или готового ответа на контрольный dataset.

## Режимы анализа

По умолчанию `deterministic`: работает без ключа и сети, извлекает явные перечни подразделений и функции из контекста обязанностей, ищет точные и близкие текстовые соответствия. `FUNCTION`, `RIGHT`, `PROHIBITION` различаются; запреты наследуются вложенными пунктами. При неоднозначном назначении функции `ownership_status=NEEDS_REVIEW`.

`semantic` использует официальный OpenAI SDK, Responses API и строгий JSON schema. Модель предлагает переименования, разделения, объединения, переносы, изменения функций, риски и аналитическое заключение. Python принимает только существующие ID объектов и источников с правильной стороны сравнения; цитаты и номера пунктов модель не генерирует. Инструкции внутри документов считаются данными. Источник: установленный SDK `openai.resources.responses.responses.Responses.parse`.

Для семантического режима задайте `OPENAI_API_KEY` и `OPENAI_MODEL=gpt-6-astra` в локальном `.env` либо окружении процесса сервера. Не передавайте ключ через API, CLI-аргумент или Git. `.env.example` — образец без секретов. Установленное окружение имеет приоритет над `.env`.

```powershell
# Сначала заполните OPENAI_API_KEY и OPENAI_MODEL в локальном .env.
$env:ANALYSIS_MODE = 'semantic'
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --env-file .env --host 127.0.0.1 --port 8000
```

Сначала проверьте доступ проекта минимальным запросом. Затем запустите полный анализ через HTTP (обе команды платные, выполняются отдельно от тестов):

```powershell
.\.venv\Scripts\python.exe -m scripts.smoke_openai --env-file .env
.\.venv\Scripts\python.exe -m scripts.smoke_api --env-file .env --mode semantic --output artifacts\api-semantic.json
```

Семантический запрос передаёт извлечённый текст документов в OpenAI с `store=False`. Для Astra используется `reasoning.effort=low`; модель возвращает строгую структуру с ID, а Python подставляет оригинальные цитаты. Доступ к модели зависит от API-проекта. Без ключа/модели возвращается HTTP 503; при ошибке нет скрытого переключения на другой режим или модель. CLI поддерживает `--mode semantic --env-file .env`.

Таймаут обращения к OpenAI — 120 секунд, автоматические повторы отключены. HTTP smoke ждёт до 150 секунд. В frontend checkpoint-1 пока установлен таймаут 45 секунд: для долгого семантического ответа PC2 должен согласовать его с backend перед следующим интеграционным checkpoint. Детерминированный путь остаётся доступен через `?mode=deterministic`; `/api/demo` всегда использует его.

## Evidence lock и границы MVP

Каждый источник содержит `document`, `section`, точный `text` и `clause_id`. Для проверки должны совпасть все четыре поля. Буквенные подпункты получают адрес вида `3.4.а` из реального номера родителя и буквы в документе. У текста без номера `section=null`; такая ссылка не подтверждает вывод. Текст из ячеек таблиц читается в порядке XML документа. Текст изображений не распознаётся.

`VERIFIED` в MVP используется для наблюдаемого сохранения названия подразделения и точного сохранения функции с явным владельцем в обеих редакциях. Пустая, неверная или нерелевантная ссылка не даёт этот статус. **Все интерпретационные findings и семантическое заключение остаются `NEEDS_REVIEW`**, даже если их цитаты существуют: цитата сама по себе не доказывает перенос, потерю, конфликт или дублирование. Отсутствие соответствия в этих документах не доказывает прекращение функции в организации.

Счётчики изменений в `summary` отражают кандидатов, включая непроверенные. БВА учитывается как родительский блок, поэтому контрольные перечни дают 3 и 5 единиц, включая сам БВА. Извлечённые функции включают записи прав и запретов, помеченные `kind`. Неявные подразделения, свободная форма полномочий и сложная нумерация могут требовать ручной проверки; ограничения отражены в `warnings`. Не поддержанные форматы нумерации не реконструируются догадками.

Один запрос обрабатывается синхронно в рабочем потоке. Очереди, БД и внешнего поиска нет. `agent_trace` — список выполненных стадий в готовом ответе, не поток прогресса и не chain-of-thought. API не сохраняет загруженные документы и результаты постоянно.

Ограничения: 10 MiB на DOCX, 40 MiB суммарного распакованного содержимого на DOCX; семантический payload до 600 000 символов, без молчаливого усечения. Поддерживаются DOCX, не PDF/XLSX/OCR. Сервер MVP предназначен для локального запуска.
