# OrgLens AI

Explainable Organizational Change Agent · HackAlem AI 2026 · спецтрек «Казахтелеком».

## Problem

После реорганизации нужно сопоставить подразделения и функции двух редакций документов: кто сохранился, кому передали ответственность, где появились потери, дублирование и потенциальные конфликты. Вывод без ссылки на исходный пункт трудно проверить.

## Solution

Русскоязычная панель сравнения «до → после»: граф преобразований, таблица функций и карточки выводов. Для каждого существенного вывода можно открыть документ, пункт, фрагмент, объяснение и рекомендацию. Итоговое заключение собирает результаты в одном месте.

## What is implemented

- Выбор пары DOCX/PDF/TXT до 20 МБ каждый для API и однокнопочный синтетический демосценарий.
- Поэтапная индикация обработки и повторный запуск через «Сбросить демо».
- Сводные показатели, граф подразделений, сопоставление функций и список выводов.
- Панель оснований с явным статусом «Требует проверки» (`NEEDS_REVIEW`).
- Аналитическое заключение со скачиванием в Markdown; состояния загрузки, недоступности API, некорректного ответа и пустого списка выводов.
- Mock-адаптер и точка подключения настоящего API. Backend в этом репозитории не реализован.

## Architecture

React + TypeScript + Vite. UI получает общий объект анализа через сервисный адаптер; деморежим возвращает локальный JSON. API-адаптер отправляет `POST /api/analyze` с `multipart/form-data`: `before_file` и `after_file`.

Контракт результата: `analysis_id`, `before_document`, `after_document`, `units`, `transformations`, `function_matches`, `findings`, `summary`. Перед показом валидатор проверяет поля, ссылки на ID, основания и согласованность счётчиков. Точные поля и правила для CORE: [API_CONTRACT.md](API_CONTRACT.md); исходные типы — [src/types.ts](src/types.ts).

## Run

В каталоге проекта:

```sh
npm install
npm run dev
```

Откройте локальный адрес из вывода Vite. Проверка и сборка:

```sh
npm test
npm run build
npm run test:e2e
```

`npm test` проверяет адаптер и контракт. E2E использует Playwright с установленным Google Chrome (`channel: 'chrome'` в [playwright.config.ts](playwright.config.ts)), самостоятельно запускает Vite на портах 5175 (demo) и 5176 (API); оба порта должны быть свободны. Ответы API перехватываются тестами, реальный backend не требуется.

По умолчанию включён mock. Для явной настройки создайте `.env.local` по образцу `.env.example`:

```dotenv
VITE_USE_MOCK=true
```

Для подключения подготовленного командой CORE сервера установите `VITE_USE_MOCK=false`. Запросы идут на `/api/analyze`; при отдельном адресе сервера задайте `VITE_API_BASE_URL`, например `http://localhost:8000`. Сервер должен разрешать запросы с адреса frontend через CORS либо быть доступен за общим origin. После изменения переменных перезапустите Vite; для готовой сборки выполните `npm run build` заново. Секреты в `VITE_*` не хранятся: эти значения попадают в клиентскую сборку.

## Data

Все данные, названия документов и цитаты в демосценарии синтетические. Это не документы Казахтелекома. Сюжет: 3 подразделения становятся 4; «Цифровое развитие» разделено на «ИТ» и «Цифровые продукты», «Внутренний контроль» переименован в «Риски и комплаенс», «Эксплуатация сети» сохранена. Набор содержит 5 передач функций, 1 возможную потерю, 2 дублирования и 1 потенциальный конфликт.

В mock-режиме выбранные пользователем файлы не разбираются и не отправляются на сервер; кнопка анализа для них отключена. Результат доступен после выбора «Загрузить демодокументы». Индикатор этапов имитирует работу агента только в этом сценарии. При анализе своих файлов в API-режиме показано ожидание ответа без вымышленных этапов.

## Limitations

- Это frontend-прототип. Реальные парсинг DOCX/PDF, извлечение, сопоставление и AI-анализ должен предоставить backend.
- Confidence в mock задан вручную и не является откалиброванной вероятностью.
- `VERIFIED` в демо означает наличие подготовленных оснований в синтетическом наборе, а не независимую проверку реальных документов.
- Отсутствие функции в новой редакции и потенциальный конфликт требуют экспертной проверки: `NEEDS_REVIEW`. Нельзя считать отсутствие найденной цитаты доказательством отсутствия функции.
- Заключение собирается из текущих данных; это не самостоятельная генерация LLM и не юридическое заключение.
- Аутентификация, серверное хранение и производственная обработка конфиденциальных документов не реализованы.
