# Вопросы жюри

**Что именно вы показываете сейчас?**

Готовый результат настоящего semantic-запуска Astra, выполненного заранее на выбранной паре DOCX. Основная вкладка содержит ответ API; резервные Markdown и скриншоты — материалы того же завершённого запуска. Мы обозначаем это прямо и не выдаём показ готового результата за новый мгновенный анализ. Проверка живого Astra-потока описана в [checkpoint 2](docs/CHECKPOINT2.md).

**Почему анализ выполнен заранее? Сколько он занимает?**

Проверенные полные запуски занимали примерно 90–101 секунду. Это наблюдавшееся время, а не гарантированная задержка. Для выступления на 2–3 минуты оставляем время на проверку результата. Frontend ждёт до 150 секунд; backend ждёт OpenAI до 120 секунд без автоматических повторов.

**Что означают LIVE ANALYSIS, DEMO DATA и semantic/deterministic?**

`LIVE ANALYSIS` означает происхождение результата из настоящего API, а не то, что запрос выполняется прямо сейчас. Режим `semantic` использует модель через backend; `deterministic` обрабатывает DOCX без LLM. `DEMO DATA` — отдельный локальный синтетический набор с имитацией этапов, без анализа выбранных пользователем файлов. Надпись «Семантический анализ» показывает режим, но сама по себе не доказывает конкретный ID модели; Astra подтверждается конфигурацией и проверенным запуском CORE.

**Что уже работает?**

React frontend и FastAPI backend: загрузка двух DOCX, анализ, сводка, граф подразделений, сопоставление функций, выводы с источниками и заключение со скачиванием в Markdown. В semantic-ответе может быть аналитическая оценка модели; UI показывает её текст, статус, источники и ограничения. Произвольный новый файл должен пройти новый анализ.

**Это настоящие документы Казахтелекома?**

Происхождение выбранных DOCX обозначаем отдельно: метка `LIVE ANALYSIS` сама по себе его не подтверждает. В `DEMO DATA` документы, подразделения и цитаты синтетические и не являются документами Казахтелекома. Подготовленный отчёт всегда относится только к указанным в нём редакциям и `analysis_id`.

**Чем точный источник отличается от правильного вывода?**

Backend связывает исходный фрагмент с документом, пунктом и `clause_id`; модель выбирает ссылки, а Python подставляет исходные цитаты. Это позволяет проверить происхождение текста. Интерпретация — например, потеря функции или конфликт — требует отдельной содержательной проверки. Точная цитата сама по себе не доказывает интерпретацию.

**Что означают VERIFIED и NEEDS_REVIEW?**

В live-анализе `VERIFIED` доступен для строго проверенных наблюдений сохранения подразделения или функции с соответствующими основаниями. Интерпретационные findings и аналитическая оценка CORE остаются `NEEDS_REVIEW`, даже если цитаты существуют. При недостаточных основаниях статус не повышается; UI показывает предупреждение. В синтетическом demo статусы относятся только к подготовленному учебному набору.

**Вы гарантируете, что потерянная функция исчезла или конфликт доказан?**

Нет. Отсутствие соответствия может быть вызвано переформулировкой, неполнотой документа или неоднозначным владельцем. Возможный конфликт — сигнал эксперту проверить совмещение ответственности, а не доказанное нарушение. Такие наблюдения остаются `NEEDS_REVIEW`.

**Какова точность и сколько находок система должна выдать?**

Фиксированного числа находок не обещаем. Выдача зависит от документов, режима и запуска модели. Confidence — оценка сопоставления, не откалиброванная вероятность и не измеренная точность продукта. Интеграционные проверки подтверждают прохождение данных, источников и отчёта через приложение; для измерения качества нужна размеченная выборка и экспертная оценка выводов.

**Как формируется заключение?**

Backend возвращает структурированные результаты и сводку; semantic-режим также может вернуть аналитическую оценку с основаниями. «Сформировать заключение» оформляет уже полученные данные и не вызывает модель повторно. Markdown сохраняет статус оценки, цитаты, рекомендации и ограничения. «Покрытие источниками» означает наличие цитат у выводов, а не долю доказанных интерпретаций.

**Показываете ли вы ход рассуждений модели?**

Нет. Пока API не ответил, UI показывает ожидание без вымышленных процентов и стадий. После завершения «Действия сервиса» отображает распознанные выполненные действия из `agent_trace`. Это журнал действий из готового ответа, не streaming и не chain-of-thought. В `DEMO DATA` этапы явно симулируются.

**Что происходит при недоступности Astra или ошибке backend?**

Ошибка отображается явно; автоматической подмены режима нет. UI различает ошибку авторизации сервиса ИИ, недоступную модель, лимит/квоту и таймаут backend 120 секунд: показывает фиксированные русские причины без сырых ответов провайдера. Можно показать подготовленный semantic-отчёт, отдельно запустить deterministic backend без LLM или явно выбрать offline `DEMO DATA`. Каждый переход объявляется. «Сбросить демо» прекращает ожидание браузера, но не гарантирует остановку серверного вычисления. Пустой список выводов не доказывает отсутствия рисков.

**Можно ли загрузить свои файлы или восстановить готовый ответ?**

UI принимает два непустых DOCX до 10 MiB каждый; PDF/TXT/OCR не поддерживаются. В API-режиме файлы отправляются настроенному backend. В mock-режиме анализ своих файлов отключён. Результат хранится только в памяти вкладки: постоянного хранения и импорта JSON/Markdown в UI нет. Для повторного открытия интерактивного результата после обновления нужен новый анализ; подготовленные Markdown и скриншоты можно смотреть отдельно.

**Куда уходят данные и что сохраняется?**

В API-режиме DOCX передаются backend; в `semantic` извлечённый текст передаётся OpenAI для анализа. В локальном `DEMO DATA` отправки файлов нет. Секреты остаются на backend. Производственный контур аутентификации и управления доступом не реализован. Подготовленные отчёты и скриншоты могут содержать исходные фрагменты, поэтому храним их только локально в ignored `artifacts/` внутри репозитория и не коммитим.

**В чём ценность продукта?**

OrgLens связывает структуру, ответственность, наблюдение и исходный пункт в одном интерфейсе. Эксперт видит результат, границы подтверждения и конкретное действие для проверки; решение остаётся за человеком.
