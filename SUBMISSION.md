# OrgLens AI

**Название для формы:** OrgLens AI

**Подзаголовок:** Explainable Organizational Change Agent

**Кейс:** «ИИ-агент анализа организационной структуры и функционала», спецтрек «Казахтелеком».

## Краткое описание для формы сдачи

OrgLens AI сравнивает две редакции организационных документов DOCX и показывает, как изменились подразделения и распределение ответственности. Система выявляет кандидатов на передачу, потерю и дублирование функций, пересечение обязанностей и потенциальные конфликты. Astra предлагает смысловые связи и аналитическую оценку, а Python проверяет ссылки и подставляет точные фрагменты документов. Граф структуры, таблица функций и панель источников позволяют эксперту проверить результат. Интерпретационные выводы явно помечены «Требует проверки»; заключение с рекомендациями и основаниями скачивается в Markdown.

## Реализованные возможности

- Загрузка двух DOCX до 10 MiB каждый и обработка через настоящий FastAPI backend.
- Извлечение подразделений, функций, прав и запретов с привязкой к пунктам и владельцам; неоднозначности отражаются в статусах и предупреждениях.
- Граф сохранения, создания, удаления, переименования, разделения и объединения подразделений; сводные показатели изменений.
- Таблица сопоставления функций до/после, фильтрация, поиск и переход к исходным фрагментам.
- Наблюдения о возможной потере, передаче, дублировании, пересечении ответственности и потенциальном конфликте интересов.
- Панель оснований: документ, пункт, точная цитата, объяснение, confidence, рекомендация и статус проверки. Неполные основания показываются явно.
- Итоговое заключение, аналитическая оценка сервиса при её наличии, источники и ограничения; скачивание в Markdown.
- Раздельные режимы реального анализа и локального demo, понятные ошибки сервиса, явный переход к резервному показу и сброс состояния.

Frontend: React, TypeScript и Vite. Backend: Python и FastAPI. Контракт загрузки — `POST /api/analyze`, поля `before_file` и `after_file`.

## Роль Astra и проверка оснований

В режиме `semantic` Astra через OpenAI Responses API предлагает отношения между подразделениями, сопоставления функций, риски и аналитическую записку. Python принимает существующие ID объектов и источников с правильной стороны сравнения, проверяет результат и подставляет оригинальные цитаты. Модель не создаёт текст исходных фрагментов и номера пунктов. Отдельные предложения с пустым обязательным текстом отклоняются с предупреждением; остальные допустимые результаты сохраняются.

Проверка происхождения цитаты и проверка интерпретации различаются. Все интерпретационные findings и аналитическая записка остаются `NEEDS_REVIEW`, даже при наличии источников. `VERIFIED` применяется только к строго проверенным наблюдениям сохранения подразделения или функции. Потеря соответствия не доказывает прекращение функции, а потенциальный конфликт не доказывает нарушение.

## Режимы и демонстрация

| Режим | Что выполняется |
| --- | --- |
| `LIVE ANALYSIS` / `semantic` | Настоящая обработка загруженных DOCX с Astra на настроенном backend. Извлечённый текст передаётся модели. |
| `LIVE ANALYSIS` / `deterministic` | Настоящая обработка DOCX backend без LLM, ключа и обращения к внешней модели. |
| `DEMO DATA` | Автономный синтетический набор и имитация этапов; выбранные пользовательские файлы не анализируются. |

Метка `LIVE ANALYSIS` обозначает происхождение результата из API, а не время его получения. Для выступления предусмотрен показ заранее выполненного настоящего Astra-анализа с явной маркировкой; подготовленные материалы не выдаются за новый ответ. Интерактивный результат остаётся в открытой вкладке. Сценарий на 2–3 минуты — [DEMO.md](DEMO.md), резерв — [DEMO_BACKUP.md](DEMO_BACKUP.md), ответы жюри — [JUDGES_QA.md](JUDGES_QA.md).

## Ограничения MVP

- Поддерживается DOCX. PDF, Excel и OCR не реализованы; сложная структура документа и неоднозначные владельцы требуют ручной проверки.
- Confidence не является откалиброванной вероятностью или измеренной точностью продукта. Число находок и время ответа не фиксированы; проверки отдельных сценариев не заменяют оценку на размеченной выборке.
- Backend ждёт OpenAI до 120 секунд без автоматических повторов, frontend — до 150 секунд. Ошибка модели не подменяется успешным ответом другого режима.
- Журнал действий доступен после завершения ответа; потокового прогресса и показа скрытых рассуждений нет.
- Производственная аутентификация, управление доступом и постоянное хранение результатов в UI не реализованы. Обновление вкладки теряет результат; импорта сохранённого JSON в интерфейс нет.
- Документы и резервные материалы с исходными фрагментами хранятся локально в исключённых из Git каталогах. Синтетические демоданные не являются документами Казахтелекома. Итоговые решения принимает эксперт.

## Проверка и воспроизведение

Текущие проверки объединённой версии описаны в [CHECKPOINT5.md](docs/CHECKPOINT5.md). Исправления повторяющихся назначений — [CORE5_HANDOFF.md](docs/CORE5_HANDOFF.md), независимые проверки владельцев, прав и запретов — [PRODUCT5_REVIEW.md](docs/PRODUCT5_REVIEW.md). Предыдущие проверки и настоящие Astra-запуски сохранены с привязкой к версиям в [CHECKPOINT4.md](docs/CHECKPOINT4.md) и [CHECKPOINT3.md](docs/CHECKPOINT3.md). Подробности контрольного синтетического сценария — [CORE3_HANDOFF.md](docs/CORE3_HANDOFF.md). Эти проверки подтверждают конкретные сценарии и происхождение текста, а не общую точность всех выводов.

Для воспроизводимой проверки без LLM установить зависимости и запустить backend по [README](README.md), затем из корня репозитория выполнить:

```powershell
.\.venv\Scripts\python.exe -m scripts.smoke_known_answer
```

Скрипт создаёт синтетические DOCX с заранее объявленными изменениями, отправляет их настоящему backend в режиме `deterministic` и проверяет ожидаемые изменения, источники и статусы. По умолчанию используется `http://127.0.0.1:8000`; другой адрес задаётся через `--base-url`. Результаты сохраняются в ignored `artifacts/known-answer/` и не коммитятся. Документы организатора и API-ключ для этой проверки не нужны. Семантическая проверка описана отдельно в CORE3 handoff и требует настроенного backend с доступом к модели.
